Polign is available inside the cluster at {{ .Release.Name }}.{{ .Release.Namespace }}.svc:23000 (HTTP) and :23001 (gRPC).
API-key authentication is required.
{{ if .Values.auth.existingSecret }}
The key in Secret {{ .Values.auth.existingSecret }} is registered and ready{{ if .Values.auth.namespace }}, bound to namespace {{ .Values.auth.namespace | quote }}{{ end }}.
Applications read it from that Secret. Nothing further has to be created by hand.
{{- else }}
No key Secret was configured, so no key exists yet. Create one now:

  kubectl -n {{ .Release.Namespace }} exec deployment/{{ .Release.Name }} -- polign-apikey -store {{ .Values.store.uri | quote }} create -namespace recall-demo

Save it securely; only its hash is retained. To avoid this step, generate a key
with "polign-apikey generate", put it in a Secret, and set auth.existingSecret.
The server then registers it at startup and the install needs no follow-up.
{{- end }}

For local access:

  kubectl -n {{ .Release.Namespace }} port-forward service/{{ .Release.Name }} 23100:23000

Set POLIGN_URL={{ ternary "https" "http" (not (empty .Values.tls.existingSecret)) }}://127.0.0.1:23100 and POLIGN_API_KEY in the environment of your Recall client.
For TLS, the certificate must cover the hostname you use and be trusted by your client.

{{- if .Values.store.claim.create }}

This deployment stores data on the volume {{ include "polign.claimName" . }}, not in a bucket, so its
durability is that volume's. That is fine for evaluation. Move to a bucket for
anything you intend to keep.
{{- end }}

This chart supports one server. Upgrades use Recreate and briefly interrupt service.
Uninstalling the chart does not delete bucket data or any volume it provisioned.
Startup restore must finish within {{ mul .Values.startupProbe.periodSeconds .Values.startupProbe.failureThreshold }}s or the pod restarts; raise startupProbe.failureThreshold for a large store.
